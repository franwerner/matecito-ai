# EDR — Seven mirror sites join the sweep with an IN/OUT verdict each

- **Status:** Accepted
- **Date:** 2026-09-09

## Contexto
prune-mining-and-ratification-gate's own delta closes its Scope table with a named list of files `sdd-apply` touches. A sweep for every place the change structurally breaks — an instruction ordering a token the contract no longer declares, a resolvable link to a path the change deletes, a table row whose subject stops existing — found seven further sites the closed Scope list does not name. Leaving all seven untouched on the reading that the Scope table is exhaustive would ship instructions that contradict the very contract they cite, and links that resolve to nothing, in the same commit that deletes their target.

## Decisión
Settle the seven in one record with a verdict each, reusing the form `structure/sweep-reach-outside-the-ratified-scope.md` already ratified. **IN (corrected in this change)**: (1) `payload/domains/development/agents/sdd-design.md:87-89,150-151` — step 4b-quater ordered emitting a `· contested:` token for `### New Decisions` after the contract dropped it; narrowed to `### Open Questions` only, which still declares the token. (2) `payload/domains/development/agents/sdd-apply.md:81-82,154` — step 5b ordered emitting the deleted `### Rejected Proposals Checked` section; rewritten to the straight-through materialization path already shipped in `SKILL.md`. (3) the `blocking-test` `none` row in `payload/domains/development/CLAUDE.md` and `phase-returns/sdd-design/sdd-design.md:229` — found already correct: an earlier dispatch in this same change (Phase 4) had already rewritten both to "reported with the rest of the section", so no further edit was needed. (4) `.matecito-ai/edr/contracts/side-discussion-handoff-shape.md:23` — a resolvable markdown link to the retired `ratification-ledger-row.md`; the row is dropped, not converted to a citation, since this file is not among the four the change deliberately leaves citing a retired record in prose. (5) `.matecito-ai/development-specs/rule/gate-firing-triggers.md:333`'s Referencias row named the retired `rule/decision-re-emergence-reconfirmation.md`; dropped. **OUT (left as accurate residue, not touched)**: (6) `phase-returns/sdd-design/sdd-design.yaml:88-89` — a comment contrasting `record-mode` against a retired record as a precedent, identical in kind to the citation-only treatment ratified for `contracts/record-mode-token.md`. (7) `.matecito-ai/development-specs/INDEX.md`'s `Inferred` legend ("minado del código as-built") — accurately describes the provenance of the 14 `Inferred` specs that stay, since the `Inferred` status itself is explicitly out of this change's scope.

## Reglas verificables
- **[manual]** `payload/domains/development/agents/sdd-design.md` orders the `· contested:` token only for `### Open Questions`, never for `### New Decisions`.
- **[manual]** `payload/domains/development/agents/sdd-apply.md` orders no emission of `### Rejected Proposals Checked` anywhere, and its materialization step reads `## New Decisions` from the design artifact directly.
- **[manual]** No surviving record under `.matecito-ai/edr/` or `.matecito-ai/development-specs/` carries a resolvable markdown link to any of the ten records this change retires.
- **[manual]** The two OUT sites (`sdd-design.yaml`'s comment, `development-specs/INDEX.md`'s Inferred legend) are left unedited — a future sweep reads them as deliberately accurate, not as residue this record missed.

## Alternativas consideradas
Treat the delta's "`sdd-apply` touches only these files" Scope line as exhaustive and leave all seven as residue. Rejected for sites 1-3: they are instructions the flow reads at runtime that contradict the contract in the same repo — exactly the case `structure/falsified-clause-joins-the-sweep.md` already covers, not the incidental-noun case `retired-vocabulary-in-record-stores.md` protects. Rejected for sites 4-5: the delta's own ADDED requirement ("no surviving record carries a resolvable link to a retired path") requires exactly this fix. Enumerate each site as its own per-change exception record instead of one record with seven verdicts — rejected: it would accumulate one record per swept site, whereas `structure/sweep-reach-outside-the-ratified-scope.md` already fixed the one-record-many-verdicts form as the reusable convention for exactly this situation.

## Consecuencias
Five real breaks the delta's own closed Scope list would have shipped are corrected in this change instead of surviving as known defects. Two accurate mentions are named explicitly as OUT so a future sweep does not re-raise them as false positives. Site 3 turned out to already be correct from an earlier dispatch in this same change, which the record states plainly rather than claiming a fix that was not needed.
